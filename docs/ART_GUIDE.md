# 아트 가이드 & 이미지 AI 작업법

지금 게임 안의 그림은 전부 **코드로 그린 임시 아트**예요 (`src/art/`).
이 문서는 이미지 AI로 정식 아트를 만들어 교체하는 방법을 정리해요.

---

## 1. 아트 방향

| 항목 | 규칙 |
|---|---|
| 스타일 | 따뜻하고 디테일한 2D 픽셀아트. 귀여운 SD(2~2.5등신) 비율 |
| 화면 해상도 | 전투 화면 160×144 픽셀 (기기에서 정수배 확대) |
| 시점 | 옆모습. 영웅은 **오른쪽**, 몬스터는 **왼쪽**을 본다 |
| 외곽선 | 1px, 거의 검은 보라색 `#1a1426` |
| 광원 | 왼쪽 위. 밝은 면은 왼쪽 위, 그림자는 오른쪽 아래 |
| 명암 | 재질마다 3~4단계. 그림자는 채도를 살짝 올리고 보라 쪽으로 (hue shift) |
| 팔레트 | `tools/palette.hex` (64색). 모든 게임 안 그림은 이 팔레트로 맞춘다 |
| 금지 | 안티에일리어싱, 그라데이션 블러, 반투명 픽셀, 1px보다 작은 디테일 |

팔레트 견본 이미지 만들기 (이미지 AI에 참고 이미지로 넣을 때 사용):
```bash
python3 tools/pixelize.py swatch -o art/palette_swatch.png
```

## 2. 필요한 그림 목록과 규격

| 종류 | 크기 | 수량(1차) | 비고 |
|---|---|---|---|
| 영웅 몸통(갑옷·망토) | 32×32 | 1 (+ 가문 시즌 외형) | 종이인형 기본 |
| 영웅 머리 모양 | 32×32 레이어 | 4 → 8 | 몸통 위에 겹침, 색은 코드가 입힘 |
| 영웅 무기 | 16×16 | 1 → 가보 단계별 5 | 손잡이 끝이 회전 중심 |
| 영웅 애니메이션 | 32×32 × 프레임 | 걷기 4, 공격 3, 피격 1 | 선택. 없으면 코드 연출로 대체 |
| 일반 몬스터 | 24~32 | 4종 | 색은 지역별로 코드가 바꿈 |
| 보스 | 40~64 | 지역당 1 | |
| 배경 레이어 | 가로 192 반복 가능, 세로 40~70 | 지역당 3장 (먼 산·중경·땅) | 좌우가 이어져야 함 |
| 아이콘 | 16×16 | 10~20 | 재화, 능력치, 특성 |
| 앱 아이콘 | 1024×1024 | 1 | 픽셀 느낌의 일러스트 (규격 자유) |
| 스토어 이미지 | 1080×1920 등 | 5~8 | 범용 AI로 키아트 + 실제 게임 화면 |

### 종이인형(레이어) 구조가 중요한 이유
이 게임은 **유전자 조합으로 영웅 외형이 정해진다** (머리색 8 × 피부 5 × 눈 5 × 머리 모양 4 = 800가지).
800장을 따로 그릴 수는 없으니, 부위별 레이어를 그리고 코드가 조합해요.

- 머리카락 레이어는 **회색조 3단계**(어두움·중간·밝음)로 그리면, 코드가 유전자에 맞는 머리색으로 바꿔 칠해요.
- 피부도 마찬가지로 3단계 회색조로.
- 모든 레이어는 **같은 32×32 캔버스, 같은 포즈, 같은 위치**여야 정확히 겹쳐요.

현재 코드의 레이어 구성 (`src/art/heroSprite.ts`): 망토 → 몸 → 머리카락 → 팔.

## 3. 어떤 이미지 AI를 쓸까

| 용도 | 추천 | 이유 |
|---|---|---|
| **게임 안 스프라이트** (캐릭터·몬스터·아이콘) | **PixelLab** (pixellab.ai) | 픽셀아트 전용. 크기 지정, 방향 회전, 걷기·공격 애니메이션, 부분 수정(인페인팅), 참고 이미지 스타일 맞추기. API와 MCP 서버도 있어서 제가 직접 호출할 수 있어요 |
| 대안 | Retro Diffusion | 픽셀아트 전용, 팔레트 지정 기능 |
| **키아트·앱 아이콘·스토어 이미지** | ChatGPT 이미지 / Gemini / Midjourney | 큰 일러스트 품질이 좋음. 게임 안 스프라이트로는 부적합 (가짜 픽셀) |
| 손보기 | Aseprite (유료) 또는 LibreSprite (무료) | AI 결과의 1~2픽셀 수정 |

> 각 서비스의 **상업적 이용 조건**을 가입할 때 꼭 확인하세요. 유료 플랜에서만 상업 이용이 허용되는 경우가 많아요.

## 4. 작업 흐름

```
① 프롬프트 고르기 (docs/PROMPTS.md)
      ↓
② 이미지 AI에서 생성  ─── 또는 ───  API 키를 주시면 제가 스크립트로 대량 생성
      ↓
③ art/raw/ 에 원본 저장 (git에는 안 올라감)
      ↓
④ 후처리:  python3 tools/pixelize.py clean art/raw/파일.png -o art/out --width 32 --preview 8
      ↓
⑤ art/out/*@8x.png 미리보기로 확인 → 필요하면 Aseprite로 1~2픽셀 수정
      ↓
⑥ public/assets/ 로 옮기고 게임에 연결 (제가 코드 작업)
```

### pixelize.py 가 하는 일
1. **배경 제거** — 가장자리에서 시작해 배경색과 비슷한 영역을 투명하게.
2. **픽셀 격자 맞추기** — AI 그림의 '한 칸'이 몇 px인지 추정(`--width` 로 직접 지정 가능)하고, 칸마다 **가장 많이 나온 색**을 골라 축소. 평균을 내지 않아서 경계가 번지지 않아요.
3. **색 정리** — `--max-colors N` 으로 번짐에서 생긴 중간색 제거.
4. **팔레트 고정** — 사람 눈 기준(CIELAB)으로 가장 가까운 `palette.hex` 색으로 바꿈.
5. **여백 자르기**, 선택적으로 `--outline 1a1426` 외곽선 추가.

자주 쓰는 명령:
```bash
pip install -r tools/requirements.txt

# 크기를 알 때 (권장)
python3 tools/pixelize.py clean art/raw/slime.png -o art/out --width 24 --max-colors 8 --preview 8

# 크기 자동 추정
python3 tools/pixelize.py clean art/raw/*.png -o art/out --preview 8

# 애니메이션 프레임 → 스프라이트 시트 + Phaser 아틀라스
python3 tools/pixelize.py pack art/out/bat_fly_*.png -o public/assets/bat_fly
```

## 5. 일관성 유지 요령

1. **기준 그림 하나를 먼저 확정**하세요 (예: 영웅 몸통). 이후 모든 생성에 그 그림을 스타일 참고 이미지로 넣어요.
2. 프롬프트 앞부분(스타일 고정 문구)은 **절대 바꾸지 말고** 뒤에 대상만 바꿔요.
3. 크기를 처음부터 목표 크기로 생성하세요 (PixelLab은 크기 지정 가능). 큰 그림을 줄이면 디테일이 뭉개져요.
4. 같은 종류는 **한 번에 여러 장** 뽑고 그중 고르세요.
5. 몬스터는 **회색조나 한 가지 색**으로 만들고 지역별 색은 코드가 바꾸게 하면 그림 수가 1/3로 줄어요.
6. 프롬프트·시드·서비스 이름을 `art/PROMPT_LOG.md` 에 기록해 두세요 (나중에 같은 스타일로 추가 생성 + 저작권 출처 증명).
7. 특정 게임·작가 이름을 넣은 "○○ 스타일" 프롬프트는 쓰지 마세요 (저작권·스토어 심사 문제).

## 6. 그림 받아들이기 체크리스트

- [ ] 크기가 규격과 같다 (32×32 등)
- [ ] 배경이 완전히 투명하다 (반투명 픽셀 없음)
- [ ] 팔레트 밖 색이 없다 (`pixelize.py` 출력의 "N색" 확인)
- [ ] 외곽선이 1px로 끊김 없다
- [ ] 방향이 맞다 (영웅 → 오른쪽, 몬스터 → 왼쪽)
- [ ] 발 위치(바닥선)가 다른 그림과 같다
- [ ] 게임 화면에서 실제 크기로 봤을 때 알아볼 수 있다
